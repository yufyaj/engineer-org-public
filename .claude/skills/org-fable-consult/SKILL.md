# Fableへ相談する

1. 組織の共通ルールに従い、重要度/自信度/難易度と、論点・根拠・不明点・候補案を短くまとめる。秘密・顧客生データ・個人の核・会話全文は渡さない。同じ論点の記録があれば先に使う。
2. Agentツールで `subagent_type: org-fable`、`model: fable` を指定し、その要約だけを渡す。fork・常設チーム・作業の委任にはしない。新たな根拠や論点がなければ同じ相談を繰り返さない。
3. 起動結果のモデル情報・実行証跡を確認する。表示がなければ `python3 "${CLAUDE_SKILL_DIR}/scripts/check_model.py" --session "${CLAUDE_SESSION_ID}" --agent "<返されたagentId>"` で当該相談のモデル名だけ確認する。Fable以外への切替、途中失敗、モデル不明は相談完了にしない。返答中のモデル自己申告だけでは確認としない。
4. 担当が回答を検証し、非公開組織repoの案件記録 `プロジェクト/<製品ID>/<プロジェクトID>/README.md` に相談事項・結論案・未解決点・採否/理由・検証後の再評価・実行参照/モデルを追記する。記録担当が別ならその担当へ渡し、保存を確認する。未検証は未検証と残す。
5. 相談で解消した場合も案件フィードバックの対象にする。呼出失敗や未確認は理由を記録し、追加調査か責任者への相談へ戻す。人の承認条件は変えない。

Agentが使えない/ネスト上限の場合は親へ同じ短い相談を返す。定義未検出は組織の `tools/install_cloud.py` で参照配置を確認し、新しいセッションで再確認する。許可・認証・モデル制限を回避せず、利用できなければ未実施と報告する。
