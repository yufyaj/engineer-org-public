# 監視・改善を設定する

組織の `AGENTS.md` と `組織/共通ルール.md` が未読なら読む。組織は現在のrepoか `~/.claude/engineer-org/`。実行方針の正本は `組織/監視と改善.md`。

## 対話で決める
既存の運用設定・接続・対象製品の指示を先に確認する。分かることを聞き直さず、未確定な点を一度に2〜3問まで聞く。
- 対象：製品、案件（機能追加・改修単位）、組織全体のどれか。repo・対象環境・担当を合わせる。
- 入口：この会話からの依頼、Chatwork、Slackなど。複数選べる。部屋/チャンネル・対象メッセージ・取得開始点を決め、指定外のチャットを巡回しない。
- チェック：セキュリティ/実行ログの対象と読取経路、Issueの作成先・作成/追記/再openの権限、チャットの回答先・送信名義/権限、緊急連絡先と通知範囲。
- 定期：監視は毎日、案件のフィードバック整理は毎週を初期値に、時刻・曜日・タイムゾーンを聞く。取得上限・実行上限・停止条件も既存運用に合わせる。組織全体への展開は人の指示時だけ行い、定期登録しない。

## 作る
1. [設定書式](references/settings.md) を非公開の組織repoの `運用/<対象ID>/設定.md` に保存する。監視対象と振り返り対象を分け、未確定欄は埋めない。案件記録から参照する。
2. 受付は必要なMCP/コネクタだけ選び、利用できる読取・返信機能と送信名義を確認する。チャットの受信トリガーがなければ、指定範囲の定期取得か手動依頼を提案し、リアルタイム受信とは呼ばない。
3. 監視・チャット回答は `org-monitor`、案件のフィードバック整理はプロジェクト責任者へ割り当てる。組織全体が対象なら、人の指示と対象のフィードバックを確認して全体統括へ渡し、定期登録へ進まない。転送専用の役を増やさない。
4. [実行指示の書式](references/run-prompt.md) に設定の参照先を入れる。指示・接続先・Issue権限・スケジュールを提示し、既に承認された範囲は聞き直さず、未承認の具体項目だけ確認する。未確定/未承認の定期実行は有効化しない。

## 登録・確認
- Claude Code標準のクラウド定期実行を使う。[公式手順](https://code.claude.com/docs/en/routines) を確認し、DesktopのScheduled → New task → Cloud、またはClaude Codeの `/schedule` で登録する。既存タスクがあれば更新し、二重登録しない。
- 非公開組織repo・必要な製品repo・環境・Opus・必要なコネクタだけを選ぶ。実行指示はファイルへの参照を中心にし、私的設定や認証値を共通スキルへ埋め込まない。
- 最初は試行中として読取・調査と回答/Issue案作成まで試す。出力先・重複判定・権限を確認して稼働中へ切り替え、最初の返信/起票結果・次回実行・再実行・停止方法を確認する。実データの問題がなければテストIssueは勝手に作らない。
- タスクID/URL・接続・有効状態・実測結果を設定に保存する。画面の「成功」だけで調査/起票成功とせず、結果本文と返信/Issueを確認する。
- コネクタ・認証・登録機能が使えなければ、設定済みと稼働済みを分けて不足を示す。ローカル常駐や別製品の自動化へ無断で切り替えない。
