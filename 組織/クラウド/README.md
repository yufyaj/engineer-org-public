# Claude Codeクラウド

1. 共通ルールを取り込んだ利用者の非公開組織リポジトリと、対象製品をクラウドセッションで使えるようにする。
2. 組織のチェックアウトで `python3 tools/install_cloud.py` を実行する。入口・役・スキルを参照配置し、異なる既存設定は上書きしない。
3. 開始時に双方の作業場所・branch・commit・未commit変更を確認し、製品の `docs/cloud-development.md` で起動・テスト・停止する。
4. 案件記録は非公開側、コードと実行手順は製品側へ保存・pushする。

セットアップ済みでも最新版やプロセスの稼働は保証されない。毎セッション版と起動を確認する。クラウド実機で未確認の動作は未確認と報告する。

監視・振り返りの初期設定は `/org-monitor-setup`。組織repoの `.claude/skills/` を使う。クラウドのProject内スレッドなどrepoのスキルが読まれない環境では、アカウント側で有効化するかSKILL.mdを明示的に参照する。参照配置だけで認識・定期登録済みとはしない。

役・スキルの追加/廃止後は `python3 tools/install_cloud.py` を再実行する。廃止した役はこの組織が配置した参照だけを外し、異なる既存設定は保持して停止する。

Fable相談は `/org-fable-consult` と `org-fable` を使う。Claude Code 2.1.271以上（指示の継承を省く設定）、Fable利用権限、Agentツールが必要。既存のClaude認証を使い、APIキーを追加しない。相談はネイティブのサブエージェントで、クラウド内から別のCLIを起動しない。
導入後は架空の論点を1件相談し、Fableでの起動・回答・担当による案件記録を確認する。`/tasks` または実行証跡でモデルを確認する。モデル強制設定・許可リストによる代替や利用上限を成功扱いしない。権限/課金の同意が必要なら本人が画面で確認し、設定を迂回しない。
[公式のサブエージェント仕様](https://code.claude.com/docs/en/sub-agents)。標準Advisorは会話全文を受け取るため、この最小要約の相談経路には使わない。
